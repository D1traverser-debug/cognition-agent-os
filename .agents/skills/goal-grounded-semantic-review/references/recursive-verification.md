# Recursive challenge, independent verification and transferable learning

Load this module for recurring failures, material cognition decisions, method transfer, independent acceptance or completion claims. Do not load it for every routine edit.

## Evidence-driven recursive challenge

On every substantive decision, question the current diagnosis and the method used to reach it. Do not assume an issue is local or architectural before inspecting competing causes. New evidence can reopen the earliest contradicted ancestor, invalidate dependent conclusions and require renewed research; preserve unaffected branches.

After a contradicted hypothesis, compare whether to inspect more original evidence, change the method, revise the workflow or challenge a governing assumption. Research unfamiliar domains at the original implementation level before selecting a remedy, then challenge the preferred adaptation again. Repeating the same claim without new evidence, a counterexample, outcome feedback or an executable plan is not progress. A resource limit is not an epistemic stopping criterion: preserve the unproved owner obligation and verified evidence needed to continue.

Record reusable methods only with exact source provenance, applicability conditions, counterexamples, failure/rollback conditions and an independent result. Transfer to a different task or domain remains NOT_TESTED until that domain verifies it. Never promote one successful fixture or a model-authored summary into a universal SOP.

## Verify before claiming completion

1. Establish a failing/positive baseline and predeclared acceptance criteria where feasible.
2. Add relevant adversarial cases: revoked grant, stale/conflicting source, reused identifier, cold resume, interrupted effect, failed external acknowledgment, inapplicable method and lawful sibling operation.
3. Run actual entrypoints and inspect observable state. Separate synthetic fixture correctness from original-source truth and real external outcomes. The independent oracle must not silently reuse the implementation's decision logic.
4. Re-run focused and broad regression, including cross-platform checks where applicable. Inspect exact-HEAD CI, not an earlier successful run.
5. Compare the complete original owner outcome with independently read-back effects. CI, self-report, documentation, a model rationale or a self-issued receipt cannot certify an owner/business result.

## Output discipline

For material decisions, provide a proportional visible receipt: goal/source; competing causes and discriminating evidence; alternatives and counterevidence; selected route, falsifier and rollback; actual action; independent readback; remaining NOT_TESTED/UNKNOWN. This is not a private chain-of-thought dump.

Do not create a sprawling prompt, parallel task registry or standalone report by default. Correct observed failures and rerun tests until behavioral acceptance is met or an evidenced blocker stops execution. For a full semantic audit, keep a per-behavior matrix and leave incomplete obligations OPEN. A concise report should state what changed, why, exact evidence, rejected alternatives, falsifying tests, skipped cases and limits.

## Empirical Skill evaluation

File presence, metadata validity, source size and green CI do not prove that a client selected or followed a Skill. Evaluate real captured agent runs with and without the Skill on positive and negative trigger cases. Compare source fidelity, actual outcomes, independent verification, unnecessary work and owner correction burden. Without first-party client traces, record native activation as NOT_TESTED.
