# cognition-agent-os — 产品目标与运行概念（ConOps）

> 文档状态：**PROPOSED / 待审阅**。版本：0.1（2026-10-20）。这里定义运行目标，不代表任何功能已实现、宿主已部署或产品需求已获批准。
>
> 上位约束：完整重建自主总控，而非修补旧仓库或仅制作软件规范监控器。旧 `universal-agent-os` 为只读研究参考。

## 1. 使命与产品边界

让用户只需定义**目标、可接受的边界和必要的授权**，系统便能在真实宿主的触发条件下，持续分解并推进合法工作：研究新问题、提出与修订计划、执行受控操作、识别未知问题、定位同类失效范围、治理并验证效果、累积可溯源知识，避免要求用户反复充当监控员。一个正常运作的总控不等于一个会循环调用 LLM 的脚本，也不等于一个只会报告问题的监控器。

**这是跨业务领域的认知父系统，不是以通用软件工程任务为最终产品的代码 Agent。** 用户既有的子系统包括：

- 视频/IP/自媒体生产：`D1traverser-debug/video-growth-agent`；
- 财经写作与内容发布：`D1traverser-debug/financial-writing-agent`；
- 长篇小说研究、创作和连载：`D1traverser-debug/novel-writing-agent`；
- A 股盘前荐股、盘后复盘与经验迭代：`D1traverser-debug/a-share-event-driven-agent`；
- 以及未来接入的任何拥有独立领域规范和执行权限的新子系统。

父系统负责**认知、主动研究与学习、方案比较、跨领域编排、目标/约束维护、专业系统指导、演进治理、纠错、任务连续性及独立总体结果验收**。子系统拥有自身领域的目标落地、业务任务 ID、规范与状态、素材/正典、来源约束、执行与发布权限和业务验收。父系统可以读取证据、提出改进和协调授权动作，但不得根据父系统摘要直接覆盖子系统的状态/资产、冒充子系统批准，或把父任务 ID 当作子任务的业务 ID。引入新业务域应采用**可发现、可验证的能力/权限/状态/结果接口**，而不是在父系统中硬编码一个永远固定的领域列表。

**旧系统迁移事实：** 四个现有子域目前各自的 `UAOS_SKILL.md` 仍指向 `D1traverser-debug/universal-agent-os@main` 作为旧控制面；`cognition-agent-os` 是它的**待验证替代父系统**，不是已经接管。旧 UAOS 只能作历史参考，不得自动获得新父系统的权威；也不得在独立切换验收及明确授权前删除旧 UAOS、修改各子域原有业务入口或无故迁移其业务资料。

**同一认知父系统的两类运行载体：** 本项目中由 ChatGPT 承担的目标理解、主动研究、方法比较、认知决策、技能和工具调度、监督纠偏，就是 `cognition-agent-os` 当前可用的交互式认知执行面；GitHub 仓库及其 Host/状态/适配器则承载**同一个父系统**可持续运行、授权、恢复与独立验证的工程实现。并不存在必须先建成另一个“ChatGPT 开发者系统”，再来建设认知父系统的先后关系。上下文遗失、被动等待用户提示、错误因果分析、局部修补及迁移失败，都是认知父系统自身待治理的缺陷。不得将 Prompt/Skill/Hook 设置成功冒充已经实际接通后台运行、已完整继承原文或实现子域独立结果的证明。

成功必须观察**父系统对子系统的实际指导与协调效果、完整业务目标结果、跨领域新知识迁移与用户负担**，不得以代码测试数、开发者 Hook 是否能跑、文档篇幅或工具调用成功率代替。初期可用免费只读适配、授权沙盒和独立业务结果证据验证父子协作；不能推断已获准操作真实交易、个人信息、外部账户或生产系统。

不在首版范围：任意外部不可逆写入、未经用户/组织授权的公开发布、自动更改访问策略、自动把自产方法晋升正式策略、多租户生产 SLA、任意模型或平台支持。后续可按可信接口扩展，不改写这些边界的历史事实。

## 2. 人、宿主与信任角色

| 角色 | 职责和约束 |
|---|---|
| 目标所有者（用户） | 确定目标、风险容忍边界、授权撤销和真正需要人工决策的事项；不负责替总控持续发现内部治理失败 |
| 运行宿主（scheduler/worker host） | 发出真实唤醒事件、保证可观测调用环境；主机离线时不伪称已运行 |
| 决策引擎（可能含 LLM） | 产生计划、提出假设、权衡知识、建议修复；**不**自行授予能力、修改正式权威或宣布结果成立 |
| 控制与任务权威 | 持久化当前目标版本、任务状态、依赖、资源预算与版本化转换；拒绝过期或不合规动作 |
| 可信执行边界 | 在全部真实写入入口执行授权/作用域检查，并记录业务意图、参数指纹、外部引用和未知结果 |
| 独立验证方 | 从源系统和产物读回业务效果；核查过程违规、负例与误报，并允许 UNKNOWN/争议结论 |
| 改进晋升权威 | 审核候选修复对整个失效类和合法邻接路径的覆盖；持有独立于候选生成者的晋升许可 |

以上是**逻辑职责**，不是必须存在七个 Agent、七个服务或七个数据库。责任应可映射至真实可审计接口。详见 [01-ARCHITECTURE-DECISIONS.md](01-ARCHITECTURE-DECISIONS.md) 和 [02-AUTHORITY-AND-INTERFACES.md](02-AUTHORITY-AND-INTERFACES.md)。

## 3. 端到端运行闭环

```text
用户/可信目标输入
    ↓ 目标版本与约束入账
宿主事件 ─→ 到期任务扫描 ─→ 领取任务/验证时效和预算
    ↓
观察上下文/证据 ─→ 决策引擎提出带理由的计划
    ↓
执行前入口授权 + 目标/知识/计划版本复核
    ├─ 不允许 → 记录受阻原因，其他合法任务继续
    └─ 允许   → 受限执行器操作/生成产物
                      ↓
             外部/文件事实独立读回
                      ↓
             VERIFIED / UNKNOWN / FAILED / NEEDS_REVIEW
                      ↓
           证据依赖修订 + 新任务/下一次唤醒
                      ↓
       执行效果和偏航信号触发系统性诊断/改进候选
                      ↓
        隔离复测 + 授权晋升（非自测即生效）
```

工作流恢复位置≠远端效果事实；会话历史≠持久任务权威；工具描述≠授权；观测到一次局部异常≠整个失效类得到治理。

## 4. 运行情境与例外（候选 OT）

这是一组**必须贯通整体设计**的场景，不是规定每条采用何种工具。

| OT | 触发/异常 | 可验证的目标响应 |
|---|---|---|
| OT01 | 用户新增或修订目标 | 可信版本入账；相关任务失效或重新规划，已发生外部效果仍留痕 |
| OT02 | 到期且用户未再发消息 | 真实宿主触发合法下一步；无 host 则明确 `HOST_UNAVAILABLE`，不自称自治 |
| OT03 | 系统发现未事先标注的新风险 | 主动搜集证据、构造不同因果假设、抑制未经证实的故障报告 |
| OT04 | 通过多个入口暴露同一失效 | 追踪共享根因、枚举 sibling 入口，并兼顾未受影响的合法动作 |
| OT05 | 外部请求成功但确认丢失 | 记录 UNKNOWN、以供应商读回/幂等合同核对；禁止不受控重试 |
| OT06 | 长任务宕机或到期触发丢失 | 持久任务重扫，复核版本和许可；不制造重复业务效果 |
| OT07 | 权限在排队或等待审批期间被撤销 | 未发送动作停止，其他授权任务可继续；在途远端请求风险如实披露 |
| OT08 | 证据源撤回、冲突或过期 | 下游推断和计划定向失效；不删除真实已发生的业务历史 |
| OT09 | 新模型/工作流/协议上线 | 比较版本兼容、旧任务语义、迁移和回退限度；验证业务结果而非仅 HTTP 200 |
| OT10 | 紧急任务挤占队列或预算不足 | 明确准入/公平/成本；拒绝超预算执行并维持可用合法工作 |
| OT11 | 任务完成声明与外部事实冲突 | 保留可审计证据，标 UNKNOWN/FAILED，优先权威结果而非自述 |
| OT12 | 用户请求停止、删除或退役 | 停止新动作，执行必要撤权/保留策略，不伪装撤销已发生的远端效果 |
| OT13 | 研究任务长期偏离原始目标 | 无需用户提醒，核验目标关联或新风险价值，停止无因果收益分支并重排 |
| OT14 | 系统提出修复或新方法 | 隔离候选 → 影响范围 → 负例/回归 → 独立证据 → 权限验证 → 灰度/晋升 → 复发检查 |

上述 OT01–OT14 是当前提议的运行情境，**不保证与历史同编号情境语义一一对应**。特别是旧 OT06（新对话只说“继续”后的原任务恢复）不同于本版 OT06（宿主宕机恢复）；旧 OT07（检索材料伪装权限指令）不同于本版 OT07（撤权）。旧情境不得因编号重用而静默丢失；须依据原始材料进行逐条需求追溯和独立验收，**不代表利益相关者已签核**。

## 5. 效果指标（MOE，需使用真实基线再定阈值）

1. **用户目标结果**：任务 owner 认可的正确业务效果及独立证据覆盖率；不能用代理自评分替代。
2. **无需催促的工作进展**：宿主产生的有效后续动作与真实任务状态变化；单次聊天响应不计自治。
3. **系统性治理**：故障类别范围覆盖、相邻允许操作的误阻断率、复发率。
4. **授权安全**：所有高风险入口的审计覆盖率、非授权外部效果数；未知远端竞态单列。
5. **持久恢复**：重启后未丢合法任务、外部效果对账正确性及重复业务效果数。
6. **知识更新有效性**：来源撤回后的依赖失效正确率、负迁移率、陌生任务结果。
7. **资源和可靠性**：任务等待/饥饿、p95 完成时间、实际消费、供应商账单与预算偏差。
8. **用户纠错负担**：用户需要提醒/修复的次数、耗时，和业务成功基线一同评价。

最初阶段不给出凭空的 p95、SLO 或“完成百分比”；2026-10-20 的首轮切片方案属于历史提案，原文件仍在 [03-FIRST-VERTICAL-SLICE.md](03-FIRST-VERTICAL-SLICE.md)，不能冒充当前执行入口。

## 6. 假设、待确认边界与版本机制

- 真正部署环境、是否要求全天候、单/多用户、初始预算、敏感信息分类及工具来源尚未获批；可进行可逆的只读/隔离工作区设计，不得据此开通持续收费服务。
- 用户建立的 `cognition-agent-os` GitHub 仓库是**公开仓库**；任何私有数据、令牌、操作密钥都不进入代码或实验资料。
- 首个代表性任务采用公共技术规范变更检查，**仅作为完整能力链验证载体**，不是总控永远只做规范监测。
- 本文所有需用户确认的设置在正式批准前标记 `PROPOSED`。当目标更新时生成新 revision 并撤销过期候选，不能静默覆盖。

## 7. 退出 ConOps/进入下一阶段的条件

可以据本文继续进行详细设计与隔离开发；**不能**凭本文宣布系统已持续自治。正式执行 P1 时须确定唯一可读真实源、隔离产物目录、预算上界和宿主触发方式；只有接入真实远端副作用前才须逐项审核该 provider 的写入权限、幂等、读回与撤权合同。详见 [03-FIRST-VERTICAL-SLICE.md](03-FIRST-VERTICAL-SLICE.md)。
