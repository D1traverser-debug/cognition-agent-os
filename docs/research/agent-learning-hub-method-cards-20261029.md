## Method card E — train a skill as a bounded, gated artifact (not uncontrolled RSI)

## Method card L — distinguish the decision-research loop from the tool-execution loop

**Primary code actually read:** [minimal agent loop](https://github.com/shareAI-lab/learn-claude-code/blob/main/agents/s01_agent_loop.py) blob `bdd525ea952c0d201ad0485e4542478bbea28431`; [context compaction](https://github.com/shareAI-lab/learn-claude-code/blob/main/s08_context_compact/code.py) blob `f4e0117def805445a19c029abdebd7b9dc003fe2`; [tool-loop boundary tests](https://github.com/shareAI-lab/learn-claude-code/blob/main/tests/test_agent_loop_boundaries.py) blob `dbb20e0b8a9afb1f2e30cf68d43d3e2d6dde094e`. These sources were **read**; their tests or live external model output were NOT run by this audit.

**Discriminating architectural insight:** The minimal loop calls tools and observes their results until a stop signal; a bounded research supervisor can reflect, delegate studies and call `ResearchComplete`, but exhausting iterations or receiving a model completion signal does **not** prove the original stakeholder's success. Its evaluator dimensions include groundedness and completeness; those are distinct from automatic production authorization. The compaction example persists older results outside the context window, and its system instruction treats summaries as reference data, not a replacement for the current owner request. Compressed context can omit a critical rejection clause; reading only the summary is therefore an unsafe inference of complete goal recovery.

**Compare and decide for cognition-agent-os:**
- **Reuse minimal tool loop** for ordinary permitted tool reads/edits; insert independent provider readback after effects; avoid a multi-agent graph by default.
- **Adapt research-supervisor reasoning** for high-impact decisions or contradictory observations: identify competing root-cause hypotheses, find the least expensive separating observation, study actual relevant implementations, compare applicability/failure conditions and challenge the winning option. Do not equate `ResearchComplete`, a model-written argument, a new citation, a green CI, or hitting a research budget with verified goal completion.
- **Reuse LangGraph-style checkpoints only when a real thread-state recovery/branching requirement is observed**; thread checkpoint and long-term cross-thread knowledge are different roles. In the current owner-woken ChatGPT phase, GitHub and the existing PRIVATE Library are already separate authorities; inventing a second Host/plan ledger is not justified by this study.
- **Keep method promotion conditional**: preserve source provenance, known failure, competing methods, applicability and counterexamples; count a method as operationally established only after a real outcome replay AND an unrelated/neighboring task succeeds. A source read alone is a research candidate, not validated transferable procedural memory.

**Observed application and falsifiers:** In the 2026-10-29 source-lifecycle incident, competing explanations included wrong root location, duplicate historical snapshots, misranking, and stale named `ACTIVE` state. Real source scoping and filesystem readback showed multiple independent old copies; removing one locator did not correct the global search. The case illustrates *why* to challenge the first hypothesis.
