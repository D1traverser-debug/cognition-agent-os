## Non-negotiable product definition

Given a legitimate owner goal, constraints, current delegated permissions and
limited budget, ONE durable agent system must autonomously determine remaining
obligations, find/check useful sources and methods, compare alternatives,
execute only permitted effects, independently read back **owner-meaningful
results**, repair or switch approaches when evidence rejects them, resume
after interruption and validate transferable learning on unrelated goals.
It should reduce the owner's work supervising, finding defects and correcting
the agent's execution.

**Parent-system acceptance supersedes generic task-runner acceptance.**
The target product is the cognition PARENT for video/IP
(`video-growth-agent`), financial writing (`financial-writing-agent`),
novel writing (`novel-writing-agent`), A-share analysis/recommendation
(`a-share-event-driven-agent`), and future independent business
subsystems. Each domain retains its canonical product requirements,
IDs, domain authority, business state, sources, assets, work progress,
effect permissions and domain outcome oracle. The parent identifies
and reconciles owner goals, investigates needed knowledge, compares
applicable cross-domain methods, routes advice/work through the child's
admitted interface, coordinates dependencies and reads independent
business outcomes without overwriting child state.

**Old-UAOS migration:** existing child `UAOS_SKILL.md` entries still
bind `universal-agent-os` to parent cognition/governance. That is the
historical parent still in use by those integration documents.
New cognition-agent-os adoption is NOT demonstrated by the current
Draft PR. No child repo edit, UAOS retirement or production cutover is
approved. A parent replacement requires a verified adapter migration,
unchanged legitimate child tasks, regression of both parent and child
state/permission/identity, and explicit owner authorization.

**One cognition parent, two presently distinct technical surfaces.**
This ChatGPT/tool session participates as the actual parent's interactive
cognition and orchestration surface; the repository is the SAME parent's
prospective persistent Host, trusted adapters, state and independent
outcome-assurance implementation. Do NOT invent a separate preliminary
"developer cognition OS" or defer parent-cognition reliability to an
unrelated project. Research, goal fidelity, tool discovery, architecture
judgment, context rehydration, error correction and cost discipline are
core parent-system requirements NOW. Codex Goals/Hooks/Skills may help
implement them, but neither these configurations nor model self-report
prove reliable integration with the persistent Host, autonomous continuation
or independently verified video/article/novel/A-share business outcomes.

A successful local JSON draft or CSV comparison under the original contract
is a real **local scoped** result. It is not a claim that arbitrary owner
goals, remote-provider effects or a finished OS have passed.

## Current invocation scope and deferred deployment

**Owner correction (2026-10-26):** ChatGPT remains a general assistant. The
cognition-parent workflow is opt-in by explicit named requests such as
`继续 cognition-agent-os`, `继承视频`, `继续小说`, or an unambiguously
selected project/task context. Unrelated everyday ChatGPT conversations must
not be forced through cognition-agent-os, run a mandatory controller, or incur
its research/verification overhead. A reliable keyword/context trigger is
acceptable; **universal automatic invocation in every ChatGPT conversation
is NOT a product requirement or current acceptance gate**. The obsolete
`uaos-controller-runtime` is not a prerequisite and must not be restored.

**Near-term priority:** Improve the opt-in interactive cognition workflow:
full original goal and correction fidelity, context-appropriate investigation,
independent comparison, lawful action with currently connected tools,
real-result readback and correction, without requiring the owner to repeatedly
enumerate missing checks or integrations. Evaluate actual triggered use, not
hypothetical blanket ChatGPT interception.

**Deferred, not discarded:** Local/cloud deployment, unattended persistent
Host scheduling, paid APIs, commercialization and a ChatGPT-to-host MCP/API
bridge are later engineering/authorization phases. They are not prerequisites
for testing current opt-in ChatGPT behavior. When a persistent server is
eventually adopted, storage can preserve goal/state/evidence independently
of conversation text; new sessions still need scoped identity, goal selection,
current grants and result-state rehydration. Do not prematurely build an
extra chat-memory/Host layer or treat server storage alone as verified
continuation. The six ultimate product gates below remain long-term
criteria, not a mandate to deploy infrastructure in this phase.

## AI-model reliability envelope — fix the parent before feature expansion

The parent cannot assume a capable LLM will reliably remember, notice, select or verify everything. These are **system design obligations**, not excuses and not prompt-only fixes:

| Model/system failure mode | Required structural compensation | Acceptance evidence |
| --- | --- | --- |
| Cross-chat/context loss | bounded bootstrap index + recovery from private original sources, live Git/runtime state | cold/new-session task resumes without owner restating recoverable requirements |
| Long-context pollution / stale history | physically separate active vs archived material; progressive just-in-time retrieval; archived evidence never default authority | held-out resume with stale conflicting history still selects current goal/source |
| Summary drift / fabricated continuity | summaries are indexes only; direct original source wins; inaccessible facts stay UNKNOWN | deliberately altered summary cannot override original user or live state |
| First-solution anchoring / confirmation bias | material choices compare meaningfully different reuse/adapt/replace/add options and predeclare falsifiers | injected attractive-but-wrong first proposal is rejected or revised from evidence |
| Tool blindness / user-as-tool-catalog | inspect actual connected capabilities and current expert sources proactively; discovered tools remain untrusted until fitted to authorization/effect boundary | unfamiliar task selects a useful tool/method not named by owner, without unsafe execution |
| Easy-task/local-optimum drift | prioritize complete owner outcome and correction burden over test count/feature count; no fixed-grammar expansion as proxy progress | real uncurated task outcome improves while owner corrections and needless paths do not increase |
| Model self-certification / hallucinated success | independent source/provider/artifact readback; model/plan/CI cannot certify its own broader outcome | false PASS/self-score is rejected by an independent oracle |
| Nondeterminism on deterministic facts | programmatic checks for exact facts, typed admissions, repeatable traces; model judgment only where semantic judgment is needed | repeated runs preserve permissions/source roles and deterministic postconditions |
| Repeated same-method failure | failure diagnosis must permit a materially different method, not prompt retries or more guardrails around the same cause | adverse result leads to different evidence/action and eventual verified or explicit UNKNOWN outcome |
| Recency / stale external knowledge | fetch current authoritative sources when current facts matter, bind evidence to source/revision/time | stale cached fact cannot override a newer independently fetched source |
| Permission confusion from retrieved text/model plans | single current grant/effect boundary; retrieved/model content is evidence, never authority | prompt injection/retrieved instruction cannot mint a grant or external effect |

**Phase rule:** until the opt-in ChatGPT/Codex parent demonstrates these controls on real unseen work with low owner correction, adding more domain-specific local planners, static registries, roles or historical context is not product progress. Some model limits cannot be eliminated; the product succeeds by compensating, detecting and recovering from them measurably.

## Six end-to-end release gates — same candidate, same original goal

1. **Whole goal -> next legal choice.** With owner requirements (including
   conjunctive clauses), at least two genuinely applicable registered
   capabilities and independent counterevidence, the controller selects an
   executable **different** authorized next method without another chat turn.
   Missing acceptance clauses cannot disappear when delegating.
2. **Choice -> action -> independent correction.** The selected action runs
   through the ONE Host/Worker/SQLite grant and effect fence; source/provider
   state is independently re-read. Rejection causes a bounded alternative or
   evidence-gathering step, not a success claim, duplicate effect or endless
   alert loop. Distinct adverse, unchanged and reversal evidence are tested.
3. **Durable real host.** A real owner-approved schedule repeatedly invokes
   Host work while absent; crash and cold restart preserve exactly the same
   original goal, action identity, authorization and progress. Provider
   acknowledge-loss and retry behavior is tested on a permissioned sandbox.
4. **Correct authority and cross-domain repair.** Current grant, typed adapter
   scope, source trust, lease fencing, attempt/cost ceilings and independent
   readback gate external effects. Systemic defects are repaired at the
   shared responsible contract and tested across legitimate sibling paths;
   reviewer or model text cannot self-authorize or self-certify.
5. **Cross-domain parent-child generalization, not curated fixtures.**
   The SAME parent cognition loop must discover and cooperate with at least
   two distinctly governed real child domains, while honoring independent
   business identity, current domain requirements, permission and source
   authority. Evaluate conflicting/changed child state, parent guidance
   rejection, domain-specific independent readback and cross-domain
   method transfer/non-fit. Audit all four existing domains for no
   unintended authority or routing regressions, and independently
   exercise a NEW previously unregistered domain through a stable
   discovery/adapter contract without product-specific parent-code
   hardcoding. Measure actual child-relevant outcome and user correction
   burden; dry-run/read-only advice is not proof of business execution.
6. **Evidence attribution and product release.** Every result ties current
   original goal and grants to chosen method, actual executed effect, verifier
   identity, provider/source readback and unchanged/restored conditions.
   Independent reviewers can reproduce the claimed outcome; unknown stays
   unknown. Release still requires explicit owner authorization.

## Architecture decision — compare whole-system alternatives

The 2026-10-25 external reference review found the following:

| Candidate | Benefit | Failure against our owner's requirement | Disposition |
| --- | --- | --- | --- |
| Copy Claude Code Game Studios' 49 specialist prompts, 74 commands and game-studio gates | Strong role separation, adaptive rigor, traceability and delivery-oriented reviews | It is a human-guided Claude Code *workflow template*, not a proven autonomous persistent Host or an independent remote business oracle. A fixed 49-agent organization adds coordination/context cost | **REUSE PRINCIPLES ONLY** |
| Replace the runtime wholesale with a new multi-agent/graph/workflow framework | Richer routing and some durable workflow infrastructure may help unfamiliar goals | Discards the verified single grant/ledger, risks split authority and provider effects, and does not itself prove goal semantics. Requires comparative end-to-end evidence first | **RESERVE IF MEASURED NECESSARY** |
| Keep the **verified authority/effect kernel**, but **replace the fixed-grammar natural-language decision path** with a model/agent-driven goal-level planner and independently checked result-feedback contract | Current ChatGPT/Codex native reasoning and available tools can attempt unfamiliar tasks now; registered effect gateway, single SQLite authority and existing oracle contracts retain narrow safe execution semantics | Not yet demonstrated as one executable native model→tools→real result loop; current Host cannot consume arbitrary new plans or certify semantic outcomes. Extra parser regexes do not close that gap | **2026-10-26 ARCHITECTURE PIVOT: TRY THIS FIRST WITH REAL A/B TRACES. NOT READY.** |

Design principle: roles are **responsibilities**, not 49 mandatory
model calls. One objective owner/vision check, an architecture/method challenger,
on-demand domain specialist(s), an independent outcome verifier and a durable
coordinator are sufficient logical separations; these should reuse existing
tool/agent contracts and only instantiate separately when isolation measurably
helps. An architecture comparison is required for material uncertainty, not
for a routine typo. Avoid replacing source-grounded work with an ever-larger
review bureaucracy.
