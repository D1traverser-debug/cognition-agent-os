## Method card D — a graph can coordinate research without guaranteeing proper stopping

Read [Open Deep Research agent implementation](https://github.com/langchain-ai/open_deep_research/blob/main/src/open_deep_research/deep_researcher.py) blob `279dbffd9e49e07962fb4e1cfeff79e45adc43e9`, [state definitions](https://github.com/langchain-ai/open_deep_research/blob/main/src/open_deep_research/state.py) blob `7578235e1369032276ef2c5ae3edf0c350ab7af8`, [evaluation](https://github.com/langchain-ai/open_deep_research/blob/main/tests/evaluators.py) blob `e68e1c17ea43bde035fbf139e5280fc22d70c24f`, [pairwise comparisons](https://github.com/langchain-ai/open_deep_research/blob/main/tests/pairwise_evaluation.py) blob `74065057237a921bcc22638b661fe7feeaa9b500`.

Supervisor calls `think_tool`, `ConductResearch`, `ResearchComplete`; delegates at most configured concurrency; researchers loop tools/MCP within iteration bounds; compression keeps raw notes as well as a summary. **Concrete upstream counterexample**: in `supervisor_tools` exception branch it currently has `if is_token_limit_exceeded(e, configurable.research_model) or True:`, making *any* caught exception terminate that research stage, potentially masking a recoverable search/tool fault. This is a source observation, not evidence of an upstream issue acknowledgment. Evaluators use a model-judge for correctness/grounding/completeness: useful proxy, **not a true business oracle**.

**Fit**: use graph only to encode non-negotiable effects/limits and clearly observable stage transitions; allow open-ended model reasoning for choice/critique, and require independently verified outcome. **Reject** copying an upstream graph blindly. **Next test**: recoverable tool outage must retry/fallback with log; genuine authorization denial must not be bypassed; postcondition must not be self-awarded at `ResearchComplete`.

## Method card E — train a skill as a bounded, gated artifact (not uncontrolled RSI)

Read [SkillOpt training-loop](https://github.com/microsoft/SkillOpt/blob/main/docs/guide/training-loop.md) blob `3ba0d524d36a5dc4774f918931d22732670e4006` and [SkillOpt-Sleep for Codex](https://github.com/microsoft/SkillOpt/blob/main/plugins/codex/skills/skillopt-sleep/SKILL.md) blob `ac4a2bccfc0c9fb4fafd8f524b677f680a43b94b`. Sequence: rollout with trajectories, reflect on failures **and successes** unless failure_only, aggregate overlapping patches, clip number of edits, update skill document, score against a selection split and accept only on strict configured improvement when gate enabled. When disabled, current can advance without replacing best: keep both snapshots. Sleep flow harvest -> replay -> consolidate -> stage -> inspect -> adopt, and warns transcript redaction is **not** guaranteed.

**Fit**: apply incremental skill/method improvements only after held-out owner-outcome tests, explicit adoption and rollback artifact. **Reject** model self-scoring as ground truth, automatic ingestion of private transcript into a provider, weight-level “self-training” claims and infinite self-improvement claims. **Next test**: a new Skill fixes exact training prompts but fails independent paraphrase; keep best, reject candidate, preserve failure trace for next decision.

## Method card F — selection of context is experimentally testable, not solved by a larger window

Read [GPT Researcher context-filter design and benchmark](https://github.com/assafelovic/gpt-researcher/blob/main/docs/docs/gpt-researcher/gptr/context-filter.md) blob `d60a90ed9c4c50ae3c652370f83eceef5e880491`, actual [lexical BM25 implementation](https://github.com/assafelovic/gpt-researcher/blob/main/gpt_researcher/context/lexical.py) blob `6fd6f36ff6b4a805b9b27d8acd9fe56df3e76727` and [controlled replay script](https://github.com/assafelovic/gpt-researcher/blob/main/evals/context_filter/replay.py) blob `9fe486b93b517ec2e6c876bf2d84a1b7e3df2c67`.

Design holds scraped pages and writer model fixed while varying context filters: 28 tasks, 20 fact-answer + 8 open-ended. Reported relevant-passages precision Jev 73%, local dependency-free BM25 51%, embeddings 46%; “no filter” could perform better for broad work but costs more context. This is the upstream's reported experiment, **not independently rerun**. Its paid Jev API and writer benchmarks cannot be quietly activated under no-paid-model authorization. Pure Python BM25 query ranking (`k1=1.5,b=0.75`), relative threshold `0.5 × best` and at most 25 passages are a candidate only; evidence sources must remain accessible after ranking. Retrieval misses a required original clause if query/candidate corpus excludes it.

**Fit**: measure relevant-source recall and omitted-owner-clause rate, not only precision. Compare no-filter / lexical / hybrid with identical test sets and source snapshots; examine the hard negatives: old “latest” index, a new original correction, a dependent revoked claim, URL redirect, and code ignored beyond the README. **Reject** an embedding DB by reflex or “all 96 links studied” based on indexing alone.
