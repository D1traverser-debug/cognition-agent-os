# Goal-grounded semantic review

This is an on-demand method, not a second controller, standing prompt, grant, release gate or claim that all files were read. Do not trigger merely because a task mentions code, a goal or a database. Follow repo-root AGENTS.md and actual owner permissions.

## Start at the original source, not the last summary

1. Resolve the live GitHub integration head, relevant ancestry and exact revision of each file. Retrieve the user's original objective and later explicit amendments, rejections and constraints. If private originals are unavailable, mark UNVERIFIED_ORIGINAL_SOURCE; do not treat a paraphrased ConOps as proof.
2. Recover the earliest applicable design decision, genuine failure logs and actual implementation/test diffs. Historical headings and proposed identifiers are not current instructions. Historical claims need date, source, applicability and explicit supersession.
3. Define the smallest meaningful behavior boundary: goal/input, authority, state, tool calls, side effects, observable outcome, lawful adjacent operations and failure/recovery paths.

## Multiple faults remain separate obligations until disproved

When the owner names multiple defects or repeatedly corrects the agent, recover every item from direct utterances. For each, record observable failure, competing causes, evidence coverage, materially different remedies, a preferred-route falsifier and acceptance status. Shared root causes must be demonstrated, not inferred from similar labels. Study original implementations and independent failure cases; challenge the selected remedy with a neglected neighbor case. Unresolved items remain OPEN.

## Load the relevant method modules

- For unfamiliar methods, research gaps, architecture choices, conflicting requirements or requirement decomposition, load [research-method-selection.md](references/research-method-selection.md). It contains the source-discovery funnel, expert questions, requirement trace contract and intervention comparison.
- For recurring failures, causal escalation, method transfer, independent acceptance or completion claims, load [recursive-verification.md](references/recursive-verification.md).
- For actual Agent/Harness design gaps, the research module points to the pinned Agent-Learning-Hub source atlas at [agent-learning-hub-primary-sources.md](references/agent-learning-hub-primary-sources.md). Read only relevant primary implementations and falsifiers; do not load the whole atlas by default.

These references are progressive-disclosure modules, not additional controllers, task ledgers or permission grants. Research is part of diagnosis and solution selection, not a substitute for either.

## Minimum decision and evidence contract

For each material obligation, connect its original source to the current authority, implementation path, relevant tests, independent oracle and owner outcome. Compare reuse/adapt/replace/remove/build as relevant; challenge the preferred option and research coverage before action. Execute only within current grants. Read back the real provider/state/effect and compare it with the original outcome. If evidence contradicts a premise, reopen the earliest affected decision rather than merely retrying a child operation.

Do not equate source inventory with semantic coverage, green CI with owner acceptance, a successful fixture with cross-domain transfer, or Skill presence with native client activation. Missing first-party activation/effect evidence remains NOT_TESTED or UNKNOWN.
