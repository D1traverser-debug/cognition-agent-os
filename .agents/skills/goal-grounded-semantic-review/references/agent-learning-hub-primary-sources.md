### GPT Researcher retrieval-contract fault — source discovery must reach actual bytes

The Hub also links two deep-research implementations. At this check, [`langchain-ai/open_deep_research`](https://github.com/langchain-ai/open_deep_research) is **ARCHIVED / read-only** (2026-08-21 on GitHub); its scoping → researching → synthesis architecture is a valuable *reference*, not an active upstream or a drop-in Host replacement. It uses configured research models/search APIs and may incur usage charges. Compare its design with the maintained [GPT Researcher](https://github.com/assafelovic/gpt-researcher/tree/3582a6841fe7dc801e2a34e34ee408641aea9bce) instead of assuming hub recommendations have unchanged release/support status.

The actual GPT Researcher [`gpt_researcher/retrievers/base.py`](https://github.com/assafelovic/gpt-researcher/blob/3582a6841fe7dc801e2a34e34ee408641aea9bce/gpt_researcher/retrievers/base.py) explicitly describes a *real past retrieval bug*: inferring "already fetched content" from `len(raw_content) > 100` caused long search snippets to bypass page scraping and lose verifiable citations (issues #1846/#1892). The corrected retriever contract declares `requires_scraping` (default `True` for new subclasses, while omitted declarations retain legacy heuristic behavior for compatibility). Its [`skills/deep_research.py`](https://github.com/assafelovic/gpt-researcher/blob/3582a6841fe7dc801e2a34e34ee408641aea9bce/gpt_researcher/skills/deep_research.py) generates multiple queries, runs them under a semaphore, gathers source URLs/citations, generates follow-up questions, and stops if all research branches fail. None of those steps alone verifies a real owner-business effect.

**Applied falsifier for cognition-agent-os:** Label each future research observation with its actual phase (`SEARCH_RESULT_METADATA`, `SOURCE_BYTES_FETCHED`, `EXCERPT_INDEPENDENTLY_PINNED`, `SEMANTIC_CLAIM_UNVERIFIED`, `OWNER_OUTCOME_VERIFIED`). A long snippet remains metadata, never authoritative source text. Verify the actual canonical bytes, SHA/ref and citation before research can influence a professional method comparison; even pinned bytes are not epistemic truth. Do **not** add these enum values as a parallel store or new controller merely to document them—first use the existing native research/SQLite receipts, and only add a typed field where a RED owner task proves ambiguity. Avoid online research API charges or new public disclosures without applicable authorization.

**Knowledge-promotion rule:** Capture one causal claim with `source_url`, immutable source SHA/ref, observed implementation/test section, applicable owner failure, competing explanation, demonstrated counterexample, independent result and `UNTESTED` status where appropriate. A source is a *lead* until compared with a second meaningful alternative and exercised against the target's actual entrypoint. Revalidate upstream HEAD before reuse. Avoid copying entire third-party repos or flooding the model context. The pinned map makes source discovery reproducible; it does not mean ChatGPT's private memory, the Codex session, or the product's Host SQLite has been automatically synchronized.

For **unfamiliar professional business domains**, this hub supplies **Agent engineering methods**, not veterinary/financial/legal/engineering domain truth. Follow the learning method into the relevant discipline's standards, primary data, tools and independent expert/biz oracles. If the allowed runtime has no lawful research/action surface, record that boundary as OPEN rather than manufacturing a plan or asking the owner for a tool catalogue.
